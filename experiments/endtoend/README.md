# Workstream E — end-to-end evaluation infrastructure for the Gemma-4 tool-protocol paper

Owner: workstream E. Everything here is under `experiments/endtoend/`. Numbers live in `results.json`
(regenerated by `analysis/make_results.py`); the running log is `progress.md`.

## 1. What was built

### 1.1 Protocol proxy (`proxy/e2e_proxy.py`, `proxy/gemma_protocol.py`)
An OpenAI-compatible HTTP proxy (aiohttp) between any agent client and a vLLM server. Route
`/<cfg>/v1/chat/completions`; configs in `proxy/configs.json`:

| cfg | what the model sees / what the client gets |
|---|---|
| `pass` | plain forward to vLLM `/v1/chat/completions` (thinking_token_budget dropped; prompt_logprobs stripped) |
| `base` | **engine mode, no fixes**: the proxy renders the prompt exactly as vLLM 0.19.1 does (same template, same message conversion), generates over `/v1/completions` with token ids, emulates vLLM's `ThinkingTokenBudget` logits processor, and parses with vLLM's own gemma4 reasoning + tool parsers |
| `quar` | + history quarantine (frozen renderer `export/quarantine_renderer.py`): malformed historical calls are re-rendered (intent recovered from the raw emission when the proxy saw it, else sanitized) and their tool responses become a structured `MalformedToolCall` error |
| `ipd` | + intent-preserving decoding IPD(i+) (below) |
| **`fullp`** (= full′, pre-registered) | `quar` + `ipd` — **no argument-order patch** |
| `order` | ablation only: tool declarations AND historical calls rendered in schema order (`old_string` before `new_string`) via a 2-line template patch (`dictsort` → `items`) |
| `full_order` | `order` + `quar` + `ipd` — what the exploratory pilots `p12a`/`p4a` ran as "full" |

Why engine mode: our vLLM servers run without `--reasoning-config`, so vLLM 0.19.1 rejects the
`thinking_token_budget` that the official harness always sends; a passthrough cannot reproduce the scorer's 4,096-token
thinking budget. The proxy enforces it post hoc: one backend request per segment, and if the sampled thinking exceeds
the budget, the tokens after the budget-th thinking token are discarded, `<channel|>` is forced and generation resumes.
This is identical in distribution to the logits processor, which never intervenes before the budget is reached.

**Intent-preserving decoding (IPD) = verify-then-repair** (workstream B's reference algorithm (i+),
`intent_decode.rollback_resume`; B's strict guard and site finder are vendored byte-identical in
`proxy/vendor_b_gemma_protocol.py`, provenance and sha256 in `proxy/VENDOR_B.txt`):
1. the turn is generated **uninterrupted** (no IPD stop strings, no extra requests);
2. when it ends (EOS, a user stop string, or the length cap), every tool call in vLLM's content region is checked with
   B's **strict guard** (`is_valid` = strict structural parse of the `<|"|>`-delimited call + schema: known tool,
   declared keys, no duplicates, required keys, types). **A strictly valid call is delivered byte-identical** — this
   is the P1 guarantee, and it is what protects valid strings that literally contain `` `,old_string: `` (an earlier
   decode-time design changed 184/1,200 such adversarial valid calls);
3. for the first call that is not strictly valid, B's `first_violation` (rules `closer` + `opener`, i.e. B's (i+);
   whitespace around `,` and `:` tolerated, e.g. `` `, new_string: ``) gives the left-most repairable site; sites inside
   arguments **not declared** in the schema are skipped;
4. closer sites: the cut inside the look-alike run is chosen by B's noisy-channel rule, score(k) = exact
   log P_model(call[:cut_k] `<|"|>` structural continuation | context) + log P_channel(closer = run[k:]), with token
   log-probs from forced `max_tokens=1` requests (`allowed_token_ids`) on cached prefixes and the closer prior frozen
   from B's logged slips (`configs/channel_prior.json`); opener sites: the cut is right after `KEY:`;
5. everything after the cut is discarded, `<|"|>` inserted, and generation resumes (at most 4 rounds per call, as B;
   at most 8 per turn). Extra cost falls only on calls that are not strictly valid.

Calls that remain not strictly valid (no site, rounds exhausted, undeclared key) are delivered as vLLM's lenient parser
reads them (**registered lenient-delivery policy**), except that a guarded post-hoc fallback (`intent_parse_args`,
whitespace-tolerant) may recover a valid call from the raw text — it never runs on a strictly valid call. B's opener
rule also regenerates calls that are strictly invalid but that vLLM would read correctly (e.g. a bare string value
`filepath:a.py`); separator drift (`key="..."`) is not in B's (i+) and stays as generated (opt-in rule `kwarg`).
The quarantine applies the same guard: a historical call whose raw emission was strictly valid is never rewritten, even
when the SYNTHESIS §5 criterion flags it. **No request ever uses `prompt_logprobs`** (PI rule: vLLM 0.19.1 materialises
an fp32 [prompt × vocab] tensor for it and OOM-crashed a shared server).

Every request is logged to `logs/proxy_<campaign>/proxy_<cfg>.jsonl`: raw generation, segments, budget/IPD/quarantine
events, emitted vs delivered call validity, history malformation sequence (for contagion analysis), latency, tokens.

### 1.2 Official harness, locally (`harness/`)
`harness/run_harness.py` runs the competition's `swegemma 0.2.11` `Evaluator` (ADK agent, AgentTool sub-agent,
ToolErrorPlugin, 3 continuation nudges, events compaction at 14,336 tokens, Docker sandbox, Phase-2 verification)
against the proxy. Patches (all in `harness/common.py`, `run_harness.py`): the model alias is routed to the proxy;
rootless Docker cannot apply CPU quotas (no cpu cgroup delegated) so container creation drops `cpu_period/cpu_quota`
(`mem_limit=4g` and `network_mode=none` kept); sandbox commands are serialised per container; each LLM call carries an
`X-E2E-Task` header for log joins.

Sandbox image: `swebench-sandbox:latest` built from `data/comp/docker/Dockerfile.public` + public wheels
(`docker build --network host` via the rootless daemon).

**Gradability.** With the official public wheels only, the gold patch passes for 43/129 public tasks; the reasons are
environmental (pydantic needs `typing_inspection`; newest-wins wheel injection gives starlette 1.x to old fastapi
snapshots; pytest plugins importing `rich` from site-packages). `harness/wheelsel.py` builds per-task wheel sets
(selection logic ported from the main-track scorer replica): the package under test is excluded, test-only plugins are
restricted to their repos, versions are the newest allowed by the snapshot's own `pyproject.toml` (+ transitive
requirements), plus the replica's gold-derived calibration pins. See §2.

### 1.3 Branch-at-onset, closed loop (`--replay-plan`, `analysis/build_branch_plan.py`, `run_branches.sh`)
From a recorded `base` episode, the proxy replays every response up to and including the root agent's first
`edit_file` turn (same tool-call ids, same reported usage so ADK compaction triggers identically) while the harness
re-executes all tool calls in a fresh sandbox; each replayed request is checked against the recording (tool-result
status, error type, normalised output hash, message count). The onset call is delivered malformed — as recorded
(natural slip) or with workstream A's P1 corruption (backtick closer on the first string key; vLLM's parse delivered;
the raw slip kept so quarantine can recover it) — and the episode continues live under {`base`, `quar`, `ipd`,
`fullp`} with common per-request seeds. Verified by an in-process test and a live closed-loop run on the real
harness (mock backend).

### 1.4 Exported renderer (`export/quarantine_renderer.py`)
Pure-Python, dependency-free, frozen (sha256 in `progress.md`): `quarantine_messages(messages, tools,
raw_by_call_id=None, canonical=False)`; used by the proxy and by workstream A (P8a recovered / P8b sanitized).

### 1.5 No-nudge client (`client/nonudge_client.py`)
A minimal ReAct loop with native Gemma tool calling through the same proxy, plugged into swegemma's `Evaluator`
(same container setup, tools, patch extraction and Phase-2 verification). Same system message and tool declarations as
the harness (copied from the harness's first logged request by `client/extract_client_cfg.py`; the ADK AgentTool
sub-agent is dropped), same sampling. Differences from the harness, by design: no continuation nudges (a response
without a tool call ends the episode), no error-recovery prompts, no compaction.

## 2. Validation (numbers from `results.json`; 95% CIs are Wilson unless noted)

**Proxy fidelity (engine mode `base` vs vLLM's own `/v1/chat/completions`, real agent contexts with tool declarations):**
prompt token counts identical on 40/40 (31B), 12/12 (12B), 12/12 (E4B, whose template differs) contexts. Greedy (T=0)
generations identical 9/12 (31B), 3/4 (12B), 2/4 (E4B); the differences are greedy divergences under concurrent
batching (vLLM is not batch-invariant), not rendering or parsing differences.

**Tests:** `tests/test_protocol.py` 65/65 (offline: template patch, classification, vendored-B sha, B-guard and
site finder incl. whitespace variants and adversarial literals, mirrors == B's intent_decode, quarantine guard),
`tests/test_generate.py` 34/34 (mock vLLM backend: thinking-budget emulation, verify-then-repair, P1 identity,
B's gate example, noisy-channel cut, opener rule, rounds cap, user stops, multi-call turns),
`tests/test_proxy_e2e.py` 30/30 (whole request path in-process incl. branch replay and an adversarial-literal
round trip; zero confirmation requests, zero `prompt_logprobs`). **P1 acceptance** (workstream B's
`proxy_equivalence.py p1e` through `Proxy.engine_chat`): `ipd` and `fullp` change 0/229,412 valid QuoteStorm calls
(adversarial 0/1,200) — `acceptance/`. Renderer compatibility for A: byte-identical to the old renderer on 12,208
A-style P1 cases.

**Gradability of the 129 public tasks in our Docker sandbox (official Phase-2 verification, gold patch):**
| wheel set | gold resolves |
|---|---|
| public wheels only (official design) | 43/129 = 0.33 [0.26, 0.42] (fastapi 1/67, rich 39/48, requests 3/13, httpx 0/1) |
| public + PyPI test deps, single set | 51/129 = 0.40 [0.32, 0.48] |
| per-task wheel sets (`harness/wheelsel.py`) | **115/129 = 0.89 [0.83, 0.93]**; empty patch resolves 2/129 → 113 discriminative tasks |

**Live IPD exercise (E4B, 20 real 31B contexts whose logged edit had slipped, one next turn each, thinking on):**
edit slips (emitted) / delivered malformed: base 2/15 / 2/15 [0.04, 0.38]; ipd 5/19 slips, 4 repaired (2 closer via
the noisy-channel cut, 2 opener rollbacks) → 1/19 delivered malformed [0.01, 0.25] (a `key_restart`, see
`failures/`); full 0/17 slips [0, 0.18] (canonical order). An earlier version with B's older 'closure' cut rule kept a
stray backtick in a repaired filepath (archived in `logs/archive_closure_rule/`), which is why the noisy-channel rule
is used.

**Failure log for the conformance corpus:** `failures/` (README there): closer_slip, key_restart, opener_drift,
key_drift, unparsed_call, unknown_tool — real outputs with full raw call text and what vLLM delivered.

## 3. How to run
- Proxy: `tools/limited.sh python proxy/e2e_proxy.py --port 8420 --backend http://127.0.0.1:<port>/v1 --served <name>
  --model-dir models/<model> --logdir logs/proxy_<campaign>`
- Harness: `python harness/run_harness.py --cfg base|full --proxy http://127.0.0.1:8420 --tasks @configs/pilot_tasks.txt
  --out runs/<tag>_H_<cfg> --sub subs/sample_noadapter --concurrency 4`
- Client: `python client/nonudge_client.py --cfg base|full ...` (same arguments)
- Pre-registered population runs: `bash run_population.sh <backend> <served> <model_dir> <sub> <tag> <tasks> <port> <conc> <seed_salt>`
  (arms base + fullp, common seeds; 31B split over two servers with `configs/eligible_113_half{0,1}.txt`)
- Branch-at-onset: `analysis/build_branch_plan.py` then `bash run_branches.sh <plan> <backend> <served> <model_dir> <sub_40calls> <tag> <port> <conc>`
- Exploratory pilots (harness + no-nudge client): `bash run_pilot.sh <backend_v1_url> <served> <tag> ...`
- Pre-registration: `PREREG_E.md` (+ `PREREG_DEVIATIONS.md`, freeze manifest via `tools_freeze.sh`); confirmatory
  analysis `analysis/prereg_analysis.py` (not run on real data before 2026-11-06 00:00 UTC)
- Analysis: `python analysis/analyze.py --runs ... --proxy-logs ... --pairs 0:1 2:3 --out analysis/<tag>.json`
- Tests: `tests/test_protocol.py` (offline), `tests/test_generate.py` (mock vLLM backend), `tests/test_proxy_e2e.py`
  (whole proxy incl. replay), `tests/test_prereg_analysis.py` (synthetic fixtures), `tests/test_parity.py`,
  `tests/test_ipd_real.py` (live), `tests/run_branch_test.sh` + `tests/mock_vllm_server.py` (live closed loop).

## 4. Limitations and deviations from the Kaggle scorer (read before citing numbers)
- **Serving.** The scorer runs vLLM with `--reasoning-config` on 4×L4; our shared H100 servers run without it, so the
  thinking budget is emulated by the proxy (identical in distribution to the logits processor, which never intervenes
  before the budget; verified by mock tests, not by a bitwise comparison with a `--reasoning-config` server).
  Prompts are rendered by the proxy (token-identical to vLLM's chat endpoint on 64/64 contexts).
- **Sandbox.** Rootless Docker cannot apply CPU quotas: sandboxes share dockerd's 24 pinned cores instead of 2 vCPUs
  each (affects command timing only). Memory 4 GB and `network_mode=none` as in the scorer.
- **Environment.** Per-task wheel sets (§1.2) replace the scorer's private prebaked environment; 115/129 gold patches
  pass, and the pilot uses only tasks where the gold patch passes and an empty patch fails.
- **Time.** Wall-clock on shared servers is not comparable to the scorer's L4 time; time budgets were set as
  non-binding safety caps (120 min) and tokens are logged so that L4 time can be estimated post hoc.
- **Submission.** The sample submission's LoRA adapters are omitted (`subs/sample_noadapter`): our servers serve the
  base checkpoints only. Budgets 50 tool calls / 100 turns (the sample's 10 calls / 1 min is a toy).
- **No-nudge client.** Same system message, tools and sampling as the harness, minus the ADK AgentTool sub-agent; it
  ends an episode at the first response without a tool call (by design) and bounds context by observation masking
  (>24k tokens), whereas the harness uses LLM compaction at 14,336 tokens and three nudges.
- **IPD coverage.** Covered (verify-then-repair, workstream B's rules closer + opener): look-alike closer slips incl.
  whitespace variants and unfinished calls, drifted string openers (also bare string values that vLLM would read
  leniently). Never touched: strictly valid calls (P1), including valid strings that literally contain
  `` `,old_string: ``. Not covered (residuals, logged in `failures/`): key restart, key drift (`start_line":451`),
  separator drift `key="..."` (opt-in rule), call text without the `<|tool_call>` opener (seen after forced
  thinking-budget ends), `call NAME{` (space instead of `:`), slips inside arguments not declared in the schema.
- **Statistics.** 40 tasks per arm, one attempt each: resolve-rate CIs are wide (±~0.15); protocol metrics are
  call-level with task-cluster bootstrap CIs. Sub-agent turns of the harness are part of the session metrics.
- **Aborted launches** of the 12B pilot (three, 10:46–11:06 UTC) are archived under `runs/invalid_*` with the reason
  and were not used for any number.
