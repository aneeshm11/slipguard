# Workstream P: Public Natural Corpus (PNC) of Gemma 4 agent trajectories

**Purpose.** The paper's confirmatory evidence must not depend on the main Kaggle competition, whose logs hold the team's
private prompts. PNC is a fresh corpus of natural Gemma-4-31B agent trajectories on public tasks (SWE-bench Verified),
generated by our own Apache-2.0 harness with our own generic system prompt and served through workstream E's protocol
proxy in its `base` configuration (vLLM 0.19.1-faithful rendering and parsing, no fixes). It is the confirmation set
of PREREG_v2 (`paper/protocol_theory/prereg/PREREG_v2.md`, sha256 5da75e61…73ac).

**Blinding.** Until production ends and PREREG_v2's own scripts run, nobody in workstream P computes, prints or looks at
any slip, malformation, parse-failure or contagion statistic of the corpus. Monitors report operational numbers only
(episodes, turns, calls, tokens, latencies, infrastructure errors, pulls). Integrity checks are structural
(`scripts/integrity.py`); at most 5 records were inspected by hand, for field presence only.

Progress log: `progress.md` (append-only). Design decisions and deviations: `DEVIATIONS.md`.

**Schemas.** Both render `new_*` before `old_*` because the template dictsorts arguments (intended).
- **S1 (primary):** `bash(command)`, `read_file(file_path, start_line?, end_line?)`, `edit_file(file_path, old_string, new_string)`,
  `write_file(file_path, content)`, `submit()`.
- **S2 (secondary, OpenHands-style):** `execute_bash(command)`, `str_replace_editor(command, path, file_text?, old_str?,
  new_str?, insert_line?, view_range?)` with commands view/create/str_replace/insert/undo_edit, `finish()`.

**Prompts** (`configs/`, written for this corpus; no text copied from the competition, swegemma/ADK or workstream E):
`system_prompt.txt` (generic, `{submit_tool}` = submit or finish), `user_prompt.txt` (the issue inside `<issue>` tags),
`nudge.txt` (sent when a response has no delivered tool call; at most 3 in a row, a 4th ends the episode).

**Harness behaviour that matters for protocol analyses.**
- The assistant turn is re-sent exactly as delivered by the proxy: `content`, `reasoning` (= `reasoning_content`) and
  `tool_calls` with the delivered JSON-string arguments. Malformed calls stay in history exactly as parsed
  (laundering is natural, as in every OpenAI-compatible client).
- Tool responses are plain text; a response is an error iff it starts with `Error:`. Validation order: unknown tool →
  missing required arguments → unknown arguments → argument types. Exact templates: `pnc/tools.py` (`T`), copied into
  each context manifest.
- After a tool response the July template ends the prompt with `<|channel>thought\n`, so the raw completion of such a
  turn starts inside the thinking channel.
- Every bash command runs in a fresh login shell in `/testbed` (conda env `testbed` active), 300 s timeout, output
  (stdout+stderr) shortened in the middle above 10,000 characters. Host identifiers (host paths, user, host name) are
  redacted from tool outputs before the model sees them.

**Production history (operational).** prod1 started 2026-11-04 15:25 UTC on GPU3 with harness 1.0 (orchestrator g3).
At 15:39 UTC it was drained and replaced by harness 1.0.1 (orchestrator g3x), which adds the `split` field to records
and the extension jobs; generation is identical. Episodes written by 1.0 were tagged `split="verified"` post hoc by
`scripts/tag_split.py` (adds that key only). GPU1 (orchestrator g1, from 16:06) and GPU0 (g0, from 17:54; paused
17:55-18:17 for workstream A) joined; all lanes share one claim directory, so every task is run once, and slot files
kept the total at most 14 containers (2 cores each). A user-ordered GPU maintenance stop ended production early: no new
episodes after 22:45 UTC; the 14 in-flight episodes finished normally by 22:52; everything was stopped and all PNC
images pruned by 22:56 UTC. The Verified part is complete; the extension holds the first 681 tasks of its stratified
order. Every episode's server is in `episode_meta.server`.

**Observation masking and status.** Masked tool outputs no longer show whether they were errors. Every context line
therefore carries `history_tool_status` (tool_call_id → ok|error as returned), the manifests declare the exact
placeholder (`masked_tool_output`), and `requests.jsonl` carries `compacted` (history holds masked items) and
`compacted_now` (masking applied right before this request). The share of requests with compacted=true is reported in
section 6 (operational).

## 2. Outputs (`data/pnc/`)
- `episodes/<instance_id>__<schema>.jsonl`: one line per model turn (= chat request). Fields: `episode_id`,
  `instance_id`, `repo`, `schema`, `turn_index`, `episode_seed`, `request_seed`, `request.messages` (exactly as sent),
  `request.params`, `masking`, `prompt_tokens` (server/proxy count), `response` (status, finish_reason, the delivered
  message: content, reasoning, tool_calls; usage), `raw_completion` (generated text decoded with
  skip_special_tokens=false, incl. `<|channel>…` and `<|tool_call>…`; from the proxy's log), `proxy` (operational fields:
  segments, thinking-budget events, latency, token counts), `tool_results` (per call: id, name, delivered arguments, exact
  content returned, `status` ok|error, `error_code`, `is_edit`, `edit_ordinal`, execution metadata), `nudge`,
  `edit_calls_before`, `tool_calls_before`, `timing`.
- `episode_meta/<episode_id>.json`: image and digest, base commit check, end reason, counts, timings, final patch.
- `tasks.json`: population, sampling procedure, S1/S2 lists, run order, images.
- `contexts/P-swebench-31b-{S1,S2}-v1/`: A's replay schema (`manifest.json`, `contexts.jsonl`, `raw_texts.jsonl`,
  `outcomes.jsonl`, `chat_template.jinja`); built by `scripts/build_contexts.py`.
- `MANIFEST.json`: sha256 of every file, model/server/proxy/harness provenance, sampling, seeds, tasks, images, licenses.

Keys used by PREREG_v2's ranking rule: `episode_id = <instance_id>__<schema>`, `turn_index` = 0-based request index.

## 4. How to run
```
# proxy (our instance of E's proxy, vendored), one per GPU server
scripts/start_proxy.sh pnc-g3-proxy 8470 http://127.0.0.1:8303/v1 experiments/pnc/logs/proxy_g3 VLLM:Worker_D3 160-163
# orchestrator (claims tasks from configs/run_order.json; several orchestrators can share one run)
QN=VLLM:Worker_D3 CORES=164-169 NAME=pnc-g3-run MEM=40G tools/limited.sh python run_corpus.py --run prod1 --owner g3 \
   --server-label gpu3 --proxy http://127.0.0.1:8470 --proxy-log logs/proxy_g3/proxy_base.jsonl \
   --slots 112-113,...,130-131 --slots-file runs/prod1/slots_g3.txt
# after generation
python scripts/integrity.py data/pnc
python scripts/build_contexts.py --schema S1 ; python scripts/build_contexts.py --schema S2
python scripts/build_manifest.py
```
Tests: `tests/test_tools.py` (scripted tool calls in a real container), `tests/test_masking.py` (exact-token masking),
`tests/mock_backend.py` (scripted vLLM mock for end-to-end runs through the proxy).
