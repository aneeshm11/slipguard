# Resource card: slipguard, TranscriptLab, PNC

*Draft, 2026-11-06 (pooled quarantine estimate and counts updated 22:20 UTC). Nothing is published yet. Repository, PyPI and Kaggle links are added when the user publishes.*

Each number below comes from a released file, cited in brackets. Paths are relative to the repository root.

## The resources

| | **slipguard** | **TranscriptLab** | **PNC** |
|---|---|---|---|
| **What it is** | A Gemma 4 tool-call hygiene library. It has six parts: a strict parser with a vLLM plugin; history quarantine (`slipguard.history`); an intent-preserving repair proxy (IPD); a patched chat template; `slipguard audit` for transcripts; and `audit-weights` for checkpoints. Unofficial; not affiliated with Google. | A causal benchmark. It edits one past action of a real agent state, then scores the next call against one pinned predicate: P(next call is a malformed edit). History arms: original, laundered call + error (copying), + success response (induction), dose k = 1/2/4, removal, quarantine. Contrasts are paired, with episode-cluster bootstrap CIs. | A public corpus of natural Gemma-4-31B (4-bit QAT) SWE-bench trajectories. Every turn has the exact request, the raw generation with the native `<|tool_call>` protocol, the calls as vLLM 0.19.1 delivered them, and the tool results. Optional SWE-bench grading is included. |
| **Install / run** | Core (stdlib only): `pip install ./slipguard`. Proxy and ADK hooks: `pip install "./slipguard[proxy-frozen,adk]"`. Then `slipguard verify`; `slipguard audit transcripts.jsonl --thinking`; `vllm serve … --tool-parser-plugin "$(slipguard plugin-path vllm)" --tool-call-parser gemma4_strict`. | `pip install "./transcriptlab[run]"`, then `transcriptlab run --base URL/v1 --model NAME --pool A1 --arms P0,P1,P6,P8a --out DIR` and `transcriptlab report DIR`. **Cost:** 300 states × 4 arms = **1,200 generations** per model (`transcriptlab estimate`). | Kaggle Dataset or HF mirror. Load one episode with `[json.loads(l) for l in open("episodes/<instance_id>__S1.jsonl")]`. Keys are `episode_id = <instance_id>__<schema>` and `turn_index`. CPU quickstart: `notebooks/quickstart.ipynb`, stdlib only, about 2 s. |
| **Licence** | Apache-2.0 [`slipguard/LICENSE`] | Code Apache-2.0. The states are PNC-derived: CC BY 4.0. | Annotations and structure: CC BY 4.0. Code: Apache-2.0. Third-party repository content keeps its SPDX licence. GPL repositories were excluded. Model outputs are under the model card's Apache-2.0 [`data/pnc/MANIFEST.json#licenses`]. |
| **Size** | 1.9 MB of source; the core has no dependencies. | CLI: 132 KB. States: the PNC contexts (562 MB, both schemas). Battery: 300 states from 231 episodes, 216 dose states, 600 first-edit states. | **3.0 GB**, of which 2.4 GB is episodes. **1,181 episodes, 41,290 turns.** By split: 400 Verified S1, 100 Verified S2, 681 SWE-bench test-ext S1 [`MANIFEST.json#splits`]. |
| **Evaluation** | Public turns, strict default (plugin in vLLM 0.19.1, 0.24, 0.31, 0.32 and 0.33): all 40,417 valid turns are delivered unchanged. 0 of 872 ill-formed turns are delivered silently, against 687–865 for the built-in parsers. On the 218 turns with known intent, slipguard delivers 0 wrong calls (built-in: 188–216 wrong). The opt-in text repair gets 152 exact, 0 wrong and 66 surfaced [`slipguard/results/conformance_pnc/RESULTS.json`]. End to end in the ADK harness (31B, 113 tasks × 2): **2.47 → 0.27 malformed calls per episode, 0.11× [0.06, 0.22]**; stuck episodes 14 → 0 of 226 [`experiments/endtoend/analysis/prereg_pop31.json`]. Injected slips: exact intent **90.6% [85.4, 94.1]**, against 0% for the lenient parser [`…/v24/battery_run_analysis.json`]. Quarantine removes **92% [86, 98]** of the history-driven excess, pooled over three runs of 900 states per arm (pre-specified descriptive, computed afterwards) [`…/v27_pooled_retest.json#pooled_removal`]; 98% in the first run [`…/confirm_v2_all_full.json#31B/full/C5`]. The patched template drops the thinking-off leak from 98.7% to 0.3% [`…/v25/out/analysis_v25.json#F3`]. All analyses were pre-registered. | One laundered call raises Gemma-4-31B's malformed next edit from **1.3% to 19.7%** (RD +18.3 pp [13.6, 23.2]). The dose response rises to 39.4% at k = 4 [`…/confirm_v2_all_full.json#31B`]. Coverage: 13 configurations in 5 tool formats (Gemma 4, hermes JSON, qwen3_coder XML, harmony, Mistral), with failed predictions reported. CLI: 16 CPU tests. Its job list equals the registered plan, and `report` reproduces the paper's bf16 row byte-for-byte. | **1,167 episodes graded, 499 resolved** (42.8% of graded), with the official SWE-bench evaluation scripts. These counts come from `grading.jsonl`, whose sha256 `6c1180e0…` is pinned in `MANIFEST.json#files/grading.jsonl`; the quickstart re-checks it. Every file is sha256-pinned in the manifest. |
| **Limitations** | **Gemma 4 only.** Only the frozen proxy (`fullp` / `ipd`) carries the end-to-end guarantees; the plugin, the `lite` engine and the template are derived (tested, not evaluated end to end). **Fail-loud alone can end an ADK turn**: ADK users should serve through the proxy. Resolve rate shows no detectable change (43–46% in both arms), and non-inferiority at −3 pp is not met. The effect is concentrated in the 31B 4-bit checkpoint; 12B shows none. | The histories are off-policy for non-Gemma models (written by 31B). There is one harness (generic SWE-bench tools). The CLI's Gemma 4 analysis covers the core arms P0/P1/P6/P8a. New-model registration exists only for the HF-template formats (hermes, qwen3_coder). The endpoint must accept raw prompts with vLLM sampling extras. | One model (31B 4-bit) and one harness, with our generic prompts and tool texts. Not bitwise reproducible: vLLM is not batch-invariant. Masked older tool outputs lose their status (`history_tool_status` in the contexts). 14 of 1,181 episodes have no grading record. |
